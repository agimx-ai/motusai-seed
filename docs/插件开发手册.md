# MotusAI Seed 插件开发手册

本文描述此开发分支的 Plugin API v2。产品已正式发布，但新 SDK、客户端接口和插件迁移尚未发布；本地构建通过不等于云端已接受新包。当前只维护官方插件，不修改 Seed Cloud 的发布账号、目录和审核规则。

## 工程边界

每个插件是独立 npm 工程，可以单独构建、测试和打包。源码自由拆分，最终只有一个 JavaScript 入口。插件拥有自己的业务和界面；客户端只提供通用 SDK、共享组件、隔离运行环境和安全服务。

```text
plugin/
├── manifest.json
├── package.json
├── build.mjs
├── tsconfig.json
├── src/
│   ├── main.ts           # 默认导出 Plugin 界面类
│   ├── service.ts        # 可选，默认导出 PluginService
│   ├── capabilities.ts   # 代码注册的公开契约
│   └── settings.tsx      # 插件自己的界面
├── locales/
├── assets/
├── tests/
├── README.md
└── README.zh-CN.md
```

插件不能导入 Seed 的 src 或其他插件的实现。只从 @motus-ai/seed-sdk 使用宿主公开 API；插件自己的领域依赖由自己的 package.json 管理。参考官方 Terminal 最小工程，复杂设置参考 Agent Harness、微信和企业微信机器人。

## 轻量 Manifest

```json
{
  "id": "com.example.clock",
  "name": { "$t": "plugin.name" },
  "description": { "$t": "plugin.description" },
  "version": "1.0.0",
  "minAppVersion": "<首次提供所需接口的客户端版本>",
  "author": "Example",
  "icon": "assets/icon.svg",
  "iconDark": "assets/icon-dark.svg",
  "i18n": {
    "defaultLocale": "en-US",
    "resources": { "en-US": "locales/en-US.json", "zh-CN": "locales/zh-CN.json" }
  }
}
```

minAppVersion 必须填写真实 SemVer；示例占位值不可直接构建发布。当前迁移按用户要求未升版，正式发布前需要同步 SDK 版本和最低客户端版本。

不嵌套 seed，不填写 publisherId、labels、能力、方法、错误、表单、管理视图或 Renderer 清单。apiVersion、runtime、service 和资源摘要由构建工具生成；源码不重复维护。权限和 consumes 只在需要时声明，用于执行前读取的安全边界，不描述界面。

语言文件使用 i18next JSON。插件元数据使用翻译键，基础信息和翻译可在不执行 main.js 的情况下读取。UI 使用 app.i18n；稳定错误码的文案放在 capabilities.<id>.errors.<code>。公开调用的旧 snake_case 字段和双语展示结果保持不变。

## 类式生命周期

```ts
import { Plugin } from '@motus-ai/seed-sdk';
import { ClockSettings } from './settings';

export default class ClockPlugin extends Plugin {
  onload() {
    this.addSettingTab(new ClockSettings(this.app, this));
  }
}
```

界面直接编写 DOM 或 React。ReactSettingTab、ModelSelect、SelectControl、CollectionCard、PreviewDialog、MarkdownContent 等从 @motus-ai/seed-sdk/react 导入，不再注册控件类型或传入旧 UI 声明。插件可以组合现有组件，也可以自己实现新控件，无须增加客户端业务分支。

onload 可以异步，初始化失败也必须清理已有贡献。onunload 是同步钩子；异步清理使用 register(async () => ...)。registerEvent、registerDomEvent、registerInterval 和 addChild 绑定资源生命周期。已卸载实例不能复用；重载创建新实例。设置页隐藏只结束显示资源，不能把后台任务当作用户取消。

## 隔离后端与代码注册

```ts
import { PluginService } from '@motus-ai/seed-sdk';

export default class ClockService extends PluginService {
  onload() {
    this.addCapability(
      {
        id: 'clock',
        version: 1,
        methods: [
          {
            name: 'read_current_time',
            risk: 'read',
            inputSchema: { type: 'object', additionalProperties: false },
            outputSchema: {
              type: 'object',
              properties: { iso: { type: 'string' } },
              required: ['iso'],
              additionalProperties: false,
            },
          },
        ],
      },
      { invoke: async () => ({ iso: new Date().toISOString() }) },
    );
    this.registerMethod('status', () => ({ ready: true }));
  }
}
```

公开方法通过 addCapability 同时注册契约和处理器，宿主校验后用于发现、Schema、审批、审计和计费。能力、版本、方法名、参数、风险与 annotations 是对外契约；框架迁移不应改变它们。官方方法提供翻译键引用的短名称和说明。

Plugin 与 PluginService 编译为 main.js 内彼此分离的入口依赖图；宿主按角色加载，不共享对象或实例。官方可信前端直接使用客户端文档中的 HTMLElement 容器，不创建独立网页或原生渲染视口；与产品壳共享 Renderer 和主题，并非逐插件前端沙箱。Renderer 关闭 Node，网络受统一 CSP 约束，系统操作通过受控接口。sandboxed-web 后端同样没有 Node；受信任官方 native-host 后端在独立 Utility Process 内执行。进程隔离不等于操作系统安全沙箱，不以未检查的权限字符串假装限制 Node。

UI 通过 app.service.call(method,args,signal) 调用自己的私有服务；私有方法不是公开 HTTP 或跨插件入口。后端 publish(name,data) 只通知自己的 UI app.events；通知不持久化、不跨插件广播。app.reloadService() 只重载自己的后端。

跨插件后台事件通过公开能力的代码注册 `events` 和消费方 Manifest 的 `consumes.events` 声明边界，再使用服务 `app.events.list/publish/subscribe`。方法消费声明不授予事件权限。事件名、版本、JSON Schema 与数据公开范围由提供方定义，订阅后的业务由消费方实现；SDK／宿主只做校验、在线分发和生命周期管理。订阅独立于页面，卸载和代次变化释放资源；持久恢复与去重属于插件。接口、队列限制与终止语义见 [SDK 文档](../packages/seed-sdk/README.md#跨插件后台事件)。

## 配置、凭据和恢复

- 后端 app.settings 原位访问旧加密配置记录；不要迁移到明文 data.json。保留插件 ID、配置记录 ID、档案 ID、凭据键、未知字段与数据目录。
- 配置值是插件自己的 JSON，SDK/宿主不强制 profiles、default_profile_id、values 或 schema_version。插件自己定义类型、校验与默认值，存储只检查 JSON、大小、归属与修订号。
- 插件 UI 样式由 buildPlugin 独立生成 styles.css，自定义样式可通过 styles 指定；新增样式类不需要改客户端扫描目录。共享组件和主题样式属于 SDK。插件 CSS 使用自己的类名前缀或根容器作用域，不覆盖产品壳的全局选择器；不要复制或重写客户端侧栏/窗口样式。
- snapshot/save 使用修订号，saveMany/transaction 原子更新关联配置。冲突明确失败，不静默重试覆盖；解密失败不当作空配置。
- UI 只收到插件明确返回的脱敏结果。空密码编辑应保留原凭据，不把占位符写成新密钥。
- Plugin/PluginService 的 loadData/saveData 共享按插件隔离的加密普通数据，同样使用并发修订号。
- 原有 plugin-data/<plugin_id>、Pi 会话、待回答问题、记忆、任务恢复记录继续沿用。正常卸载不等于用户取消，不得因为生命周期中止而删除或完成未回答问题。
- 文件选择使用 app.files.pick() / app.files.path(file)，只传明确选择的本地路径；已声明资源用 app.resources.url(path) / PluginService.resourceUrl(path)。

## 调用、安全与公共协议

consumes 可以精确列出 capability/method，或按通用方法 annotation 匹配；通过 app.capabilities.list/invoke 调用。不得导入提供方实现或绕过能力代理。宿主继续检查权限、参数、返回值、循环调用、审批和审计。多个提供方使用 provider_plugin_id 精确路由，不静默选第一个。

exposure: terminal 可向连接器和已授权消费方暴露；plugin 仅允许声明过的插件间调用；local 只允许本地入口。方法 platforms 限制实际平台。Agent/MCP 工具仅由显式 annotations 提供，名称必须稳定、清楚且全局唯一，重名直接失败。

文件、音频、截屏、进程、授权等高权限机制使用 app.invokeHost 的受控 Broker，所需静态权限写入 Manifest。插件专属协议、命令白名单、重连和业务错误仍由插件负责；客户端不得按插件 ID 分支。

长连接使用 registerConnection，实际工作通过 app.tasks；连接存在不等于任务忙碌。正常停止先撤下路由和监听，再等待清理。真正用户取消需传播到实际网络或子进程，并只产生一个终态。

本地 HTTP/SSE 使用 registerLocalApi，声明 local.http-api；路由不重复包含 /v1，宿主挂载为 /v1/plugins/{package_id}。Seed 拥有 loopback 监听、令牌、Origin、限流、大小限制与撤权。插件不得自行监听端口或接收客户端原始令牌。

业务 SSE 使用 SeedLocalEventStream；持久状态才是重启恢复依据。结构化 audit.record 不包含令牌、正文或绝对路径。状态轮询和长连接分别标为 background 和 stream，不作为前台任务。

已有 cloud_relay、local_relay、include_billing 和音频分段协议保持不变。价格与结算由 Cloud 决定；插件不能提交价格或把未知费用当免费。计费恢复只重试原记录，不重新执行业务。通用宿主接口和音频约束见 SDK README。

## 构建与打包

```js
import { buildPlugin } from '@motus-ai/seed-plugin-tools';
await buildPlugin({
  root: import.meta.dirname,
  runtime: 'native-host',
  service: 'src/service.ts',
  resources: [
    { source: 'README.md', path: 'README.md' },
    { source: 'assets/icon.svg', path: 'assets/icon.svg' },
  ],
});
```

默认 runtime 为 sandboxed-web；不需要后端可省略 service。React 源码可以自由拆分，资源必须声明携带。buildPlugin 生成一个 main.js、manifest.json、可选 styles.css 和必要资源；构建失败保留上一次完整输出。

每个插件单独提供 build、typecheck、test、pack。pack 调用 seed-plugin-tools pack；可选 package.mjs 返回平台变体及原生资源，仍通过同一打包器校验并生成 ZIP。根脚本只编排独立工程，并在包外生成现有 Cloud 目录快照，不再维护另一套构建／压缩实现。

## 本地开发与热重载

启动客户端开发环境：在 Seed 仓库运行 npm run dev。启动单个插件开发环境：在该插件目录运行 npm run dev，或在官方仓库运行 npm run dev --workspace=<plugin_id>。独立工程的 build.mjs 是唯一构建入口；dev 不生成 ZIP、不上传或发布。

构建完成后自动同步到用户数据目录 plugins/development/<plugin_id>。macOS 默认位于 ~/Library/Application Support/MotusAI Seed/plugins/development；Windows 使用 APPDATA，Linux 使用 XDG_CONFIG_HOME 或 ~/.config。也可手动放入完整构建目录，Seed 自动发现。工具的 --directory 参数只用于明确指定构建同步的目标目录，不是客户端挂载外部源码目录。

源码、语言或样式改动触发构建，成功后发布完整目录，Seed 重载该插件的界面和后端。同版本可反复开发，失败保留上次完整产物。原生资源复用该插件 package.mjs 的当前平台目标，不另写开发专用业务打包器。

开发插件沿用同 ID 的配置、凭据和数据；只在开发模式参与本地版本选择，不改正式安装数据库。插件的 npm run dev 正常停止（Ctrl+C／SIGTERM）时，只移除本次监听同步的开发产物；若目录已被其他开发进程重新部署，则不删除。停止时先等待构建退出，避免退出后再次同步。移走开发目录会卸载开发实例，并恢复已获授权的正式版本，配置、凭据和业务数据保留。强制杀进程（SIGKILL）或断电无法执行退出清理。生产客户端不读取开发目录。正式云端下载、校验、安装和更新机制保留；新规范包的云审核与发布仍须独立验收。

## 回归与交付

至少覆盖公开契约不变、Schema/权限拒绝、取消和失败、卸载清理、并发配置、凭据沿用、会话／提问恢复及删除防复活。SDK testing 模块挂载真实 PluginService 类，不模拟旧 apply/Cordis 接口。

UI 验证亮暗主题、宽窄布局、焦点、滚动和卸载。使用独立临时数据做 Electron 隔离 smoke，不能覆盖用户已安装插件或真实凭据。未经授权不升版、不提交、不推送、不发布。

进一步接口说明见 [SDK README](../packages/seed-sdk/README.md) 和 [插件包规范](社区插件与插件包规范.md)。

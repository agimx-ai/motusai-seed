# MotusAI Seed 插件开发手册

本文对应 Seed Plugin API v1。官方插件源码维护在独立的 `motusai-seed-official-plugins` 项目；社区插件维护在开发者自己的仓库。两者都构建为 `.seedpkg`，通过 Seed Cloud 的同一套审核与发布流程进入统一插件目录，并安装到 Seed 的同一个数据目录。

## 1. 最小目录

```text
com.example.seed.clock/
├── manifest.yaml
├── assets/
│   ├── icon.svg
│   └── icon-dark.svg
├── caps/
│   └── clock/
│       ├── clock.yaml
│       └── clock.ts
```

插件只能从 npm 包 `@motus-ai/seed-sdk` 导入公开 API，不能引用 Seed 客户端的 `src`，也不能依赖 `@deepseek-ai/*`。

## 2. Manifest

```yaml
id: com.example.seed.clock
name:
  en_US: Local Clock
  zh_Hans: 本地时钟
description:
  en_US: Read the local time on the computer running Seed.
  zh_Hans: 读取 Seed 所在电脑的本地时间。
labels:
  - productivity
  - utilities
version: 1.0.0
min_seed_version: 0.1.67
publisher: com.example
icon: ./assets/icon.svg
icon_dark: ./assets/icon-dark.svg
runtime:
  kind: sandboxed-web
caps:
  - ./caps/clock.yaml
```

`schema_version` 与 `api_version` 在 v1 可省略，Seed 会按 v1 解析。运行入口固定为 `dist/index.mjs`，插件不能另行指定。Manifest、配置声明、资源管理声明、目录 API、RPC 和能力参数中的 Seed 自有字段统一使用 `snake_case`。YAML 禁止 alias、自定义 tag 和可执行配置。

`min_seed_version` 必填，按语义版本比较。插件使用新增宿主能力时应提升此值；Seed 在安装和每次启动时强制检查，版本不足时保留插件数据但禁止运行。

所有面向用户的插件文案使用 Dify 风格的 block-style 语言映射，`en_US` 与 `zh_Hans` 均为必填项。适用字段包括插件 `name`、`description`、方法 `display_name`、能力与方法 `description`，以及配置和资源管理的标题与说明。不要使用纯字符串、`{ ... }` flow style 或 JSON 语法；缺少任一语言会导致插件包或 Seed Cloud 发布校验失败。

`labels` 由插件声明，用于搜索和筛选。每个插件必须声明 1–3 个不重复标签，可选值为：`search`、`image`、`videos`、`weather`、`finance`、`design`、`travel`、`social`、`news`、`medical`、`productivity`、`education`、`business`、`entertainment`、`utilities`、`other`。客户端仅在目录中存在多个标签时显示筛选，并始终使用一个扁平插件列表。

普通官方与社区插件各自在独立 `sandboxed-web` Host 运行：`nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`、禁止网络、窗口和系统权限。经过目录校验的官方 `native-host` 插件各自在独立 Utility Process 运行，可用于确实需要 Node.js、本机进程或网络连接的能力；Connector 只保留协议路由与校验，不加载插件代码。单个原生进程崩溃后，其能力、本地 API 和运行时贡献会撤下并独立重启。社区插件不得声明或运行 `native-host`。

根 `manifest.yaml` 只负责插件身份、运行类型、权限和能力清单引用。每项能力及其配置、资源管理声明跟随能力自身维护，不再堆叠到插件根清单中。

浏览器授权按协议标准声明权限：`authorization.oauth2.pkce` 或 `authorization.oidc.pkce`，并同时声明授权地址对应的 `network.connect.*` 范围。插件通过 `ctx.authorization.authorize()` 提交授权端点、客户端 ID、scope 和可选服务商参数；Seed 统一处理系统浏览器、自定义协议回调、`state`、PKCE S256、超时和取消。具体服务商的令牌交换、OIDC 校验、刷新及连接由插件或其服务端实现，不在 Seed 增加服务商分支。接口示例见 SDK README；扫码/设备码流程不使用该浏览器回调接口。

`icon` 是必填的插件级图标，`icon_dark` 可选；两者必须引用 `assets/` 下的 SVG、PNG、WebP 或 JPEG 文件。能力自己的展示资源也放在该目录，避免把二进制或 SVG 内容塞进 YAML。

## 3. 能力声明与实现

`caps/clock.yaml`：

```yaml
id: clock
version: 1
exposure: terminal
errors:
  method_not_supported:
    en_US: "Clock does not support method: {method}"
    zh_Hans: "Clock 不支持方法：{method}"
methods:
  - name: now
    display_name:
      en_US: Read current time
      zh_Hans: 获取当前时间
    description:
      en_US: Return the current ISO time and time zone.
      zh_Hans: 返回当前 ISO 时间和时区。
    risk: read
```

方法的 `name` 是稳定的调用标识，不随语言变化。`display_name` 是独立的双语短名称，每种语言最多 100 个字符，用于工具行、审批面板等用户界面；`description` 保留详细用途、参数说明和 Agent 指令，不能用长描述代替短名称。该字段在通用 Schema 中可选，官方插件的全部方法均声明它。`context.capabilities.list()` 原样返回双语 `display_name`，消费方按自身界面语言展示；Agent Harness 在实时工具事件、历史记录和审批请求中透传同一字段，不能改写模型调用的工具标识。没有显示名称的未知工具显示其技术标识，不按插件或工具名称硬编码翻译。

`exposure` 控制能力的可见边界：

- `terminal`：默认值。能力可被连接器插件按其自身协议暴露给远端 Agent，也可被 Manifest `consumes` 已显式声明依赖的其他插件发现和调用。Seed Core 不建立或代理远端连接。
- `plugin`：能力只允许被已在 `consumes` 中声明依赖的其他插件发现和调用，不允许连接器暴露给远端。
- `local`：能力只在 Seed 客户端本地注册，不参与插件间或远端调用。适用于由 Obsidian 等可信本地应用经插件自有回环接口调用的能力。

暴露级别定义在能力而不是插件上，因此同一个插件可以同时提供本地能力与终端能力。客户端按该字段统一过滤，不对具体插件 ID 做特判。

能力方法可选声明 `platforms`，值为 `darwin`、`linux`、`win32` 中的一个或多个；不声明表示所有平台可用。Seed 仅向消费插件和 MCP 展示当前平台适用的方法，并在调用入口拒绝不适用的方法。不同平台可在同一能力下声明不同方法，例如 Bash 与 Windows PowerShell，而不需要消费方猜测当前终端类型。

需要组合已知插件能力时，在根 `manifest.yaml` 中显式声明消费白名单：

```yaml
consumes:
  - capability: files
    methods:
      - list_filesystem_roots
      - list_directory
      - read_file
      - write_file
```

需要动态发现某类插件能力时，可以按方法 annotation 匹配。提供方必须在每个允许消费的方法上明确声明 annotation，消费方只声明通用选择条件：

```yaml
# 提供方能力方法
annotations:
  agent.tool: true

# 消费方 manifest.yaml
consumes:
  - match:
      method_annotation: agent.tool
      equals: true
```

匹配器只授权符合条件的方法，不会授权同一能力中未标注的方法。安装、停用、升级或卸载匹配的提供方时，Seed 会重新装载相关消费方，使其通过 `context.capabilities.list()` 得到当前工具集合。Seed 只执行 annotation 匹配，不解释 `agent.tool` 的业务含义。

提供给 Agent 的方法可以用 `agent.tool_name` 声明稳定别名。名称必须使用小写字母开头，只包含小写字母、数字、下划线或连字符，且不超过 64 个字符；显式声明了非法名称时消费方应直接拒绝装载，不得静默改名。名称应采用“动作 + 明确对象”，例如 `read_file`、`search_file_contents`、`list_directory`，避免 `read`、`search`、`run`、`roots` 这类脱离上下文后含义不清的名称。不同提供方以及消费方自身内置工具的最终名称必须全局唯一；重复时应拒绝启动 Agent，而不是按安装顺序覆盖。

Seed 在现有本机网关的 `http://127.0.0.1:43127/mcp` 提供 MCP Streamable HTTP 入口。插件若要把某个能力方法提供为 MCP 工具，只需在该方法标注 `mcp.tool: true`；可用 `mcp.tool_name` 指定稳定名称，并须声明双语描述及对象类型的 `input_schema`。只有显式标注的方法出现在 MCP 工具列表中，`agent.tool` 不会自动变成 MCP 工具。调用仍执行同一个能力方法，不需要插件创建 HTTP 服务或实现 MCP 协议。

官方 `native-host` 随后通过 `context.capabilities.list()` 获取当前实际安装且可用的声明子集，通过 `context.capabilities.invoke()` 发起调用。调用始终经过 Seed 能力代理：未声明的方法、本地专用能力、自调用与循环调用会被拒绝；参数和返回值继续按提供方 Schema 校验；写入与控制方法需要用户逐次确认；结果自动进入活动记录。消费方不得导入提供方代码，也不得绕过代理调用内部 Host Service。

需要自行联网的官方 `native-host` 按目标范围声明 `network.connect.internet`、`network.connect.lan` 或 `network.connect.loopback`，禁止把厂商或业务名称编码进权限。插件自行创建 HTTP、WebSocket、TCP 或 MQTT 客户端，并通过 `context.connections.register()` 登记长连接使用的权限、传输名称与生命周期。普通连接不经过 Seed 代理；Fiber 清理时会先终止连接 `signal`，再调用登记的 `close()`。插件不得自行监听端口，入站 HTTP/SSE 仍通过 `local.http-api` 向统一网关注册路由。长连接本身不使用 `context.tasks`，只有消息触发的实际处理任务才进入全局任务状态。

无需向用户提供第三方密钥配置的收费插件可以声明通用 `cloud.relay` 权限，并在需要收费的能力 YAML 方法上同时标注 `billing.settlement: cloud_relay`、`billing.relay_template` 和 `billing.product`。插件只声明消费哪个全局计费产品和转发模板；计费模式、价格、汇率、利润率与公式均由 Cloud 运维统一配置，插件声明 `billing.mode` 会被拒绝。插件在该方法调用中使用 `context.invokeHost('seed.cloud.relay', { call_id: invocation.billing.call_id, capability_id, method, payload })`。Cloud 根据已发布插件声明找到固定上游并注入凭据，插件不能提供 URL、凭据、价格、倍率或用量；返回值为 `{ payload }`。依赖的全局计费产品或转发服务未就绪时拒绝执行，不能回退到本机直连。Seed 发起调用前由 Cloud 检查余额并建立一次性调用记录，不冻结积分；Cloud 只根据可信上游结果和模板提取的用量结算。相同调用记录不会重复转发；结果或按量成本不明时进入待核对状态，不能退回按次收费。未标注的方法保持免费。

云转发流通过 `seed.cloud.relay.stream.start/next/close` 使用插件隔离的句柄。`stream.next` 返回 `{ done: false, chunk }`（base64 字节），或流结束时的 `{ done: true, billing?: { state: 'settled', charged_amount } }`。`billing` 只来自 Cloud 的已确认结算，零积分也会明确返回；未结算或查询失败时省略，插件不能把缺失解释为免费。终态在短期内可重复读取，不重复结算；提前关闭不会生成积分。

云转发的完整 JSON 请求（含调用元数据）最多为 64 MiB，与 Cloud HTTP 接口一致；具体上游模板仍可声明更小的限制。超过传输限制返回 `credit_relay_request_too_large`，不能当作网络故障反复重试。Agent 适配器应保留该错误的 HTTP 413 语义，让 Agent 运行时决定上下文压缩和恢复；宿主不管理模型上下文。

不同插件可以实现相同的 `capability` 与方法契约，例如本地和云端实现都提供 `agent_sessions`。`context.capabilities.list()` 会为每个实现分别返回全局唯一的 `provider_plugin_id`。只有一个匹配实现时调用方可以省略它；存在多个实现时必须把用户或插件选择的 `provider_plugin_id` 传给 `invoke()`，Seed 不会静默选择第一个。选择字段、文案、默认值和绑定粒度由消费插件通过声明式配置拥有，Seed 只负责通用发现、持久化配置和精确路由。

```ts
const providers = await context.capabilities.list()
const selected = providers.find((item) => item.provider_plugin_id === configuredProviderId)
if (!selected) throw new Error('The selected capability provider is unavailable.')

await context.capabilities.invoke({
  provider_plugin_id: selected.provider_plugin_id,
  capability: selected.id,
  method: 'sessions.open',
  arguments: {},
})
```

`caps/clock.ts`：

```ts
import { SeedPluginError, type SeedPlugin } from '@motus-ai/seed-sdk'

const plugin: SeedPlugin = {
  apply(ctx) {
    ctx.effect(() => ctx.capabilities.register('clock', {
      async invoke(method) {
        if (method !== 'now') {
          throw new SeedPluginError('method_not_supported', `Clock does not support method: ${method}`, { method })
        }
        return {
          iso: new Date().toISOString(),
          timezone: Intl.DateTimeFormat().resolvedOptions().timeZone,
        }
      },
    }))
  },
}

export function apply(ctx: Parameters<SeedPlugin['apply']>[0]) {
  return plugin.apply(ctx)
}
```

运行时注册的能力、版本和方法必须是 Manifest 声明的子集。静态 Manifest 是服务端展示、工具生成、审批和客户端路由的权威来源。

插件专属错误同样由能力 YAML 负责多语言定义。运行时使用 `SeedPluginError` 返回稳定错误码、英文 fallback 和用于模板插值的基础类型参数；插件代码不读取客户端语言。Seed 在错误离开插件时，根据客户端当前语言选择 `en_US` 或 `zh_Hans` 并替换 `{parameter}`。本地 HTTP API 响应会优先使用请求的 `Accept-Language`，未提供时使用 Seed 当前语言。未识别的错误码保留 fallback，原始技术详情与已本地化的用户提示分开传递。

## 4. Broker 权限

沙箱插件没有 Node.js、文件系统、Terminal Token 或任意网络访问。需要本地能力时，插件通过 `ctx.invokeHost()` 调用 Core 白名单 Broker；服务名与权限由 Core 校验，不能动态映射 Electron API。

Files 官方插件示例：

```ts
await ctx.invokeHost('seed.broker.files.invoke', {
  method: 'read',
  request,
})
```

对应根 `manifest.yaml` 必须声明 `resources.directory.read`，写入还需要 `resources.directory.write`。Broker 才持有本地文件系统根路径、备份目录和 Node.js 文件 API，插件不会获得这些数据。

官方 `native-host` 的 `apply(ctx)` 同样可以通过 `ctx.invokeHost()` 调用受控 Host Service。需要向本机应用提供 HTTP/SSE 接口时，插件声明 `local.http-api` 并通过 `ctx.effect(() => ctx.localApi.register(...))` 注册业务路由，例如 `/status`；Seed 将其挂载为 `/v1/plugins/{package_id}/status`。`/v1` 由统一本地网关拥有，插件路由不得重复声明版本前缀。网关负责客户端令牌的签发、校验、插件作用域和撤销，插件不能直接调用内部客户端授权服务，也不会收到原始令牌。

插件需要配置时，可声明 `schema_version: 1` 的版本化配置。`seed.profiles` 用于可展开的配置档案：插件声明集合级字段、档案字段、默认档案、数量约束、选择项默认值、条件显示/必填规则，以及 Profile 和配置级字段各自可用的保存、添加、移除、设为默认动作。`seed.option-list` 用于一个由插件动态提供、无需其他字段依赖的单选列表；选中项会保存为该配置唯一的默认档案。`seed.catalog-list` 使用同一动态数据来源展示只读目录，不提供选择交互，也不写入配置或默认项；目录与配置档案组成同一来源组时，来源切换也只改变当前展示。Seed 只负责按声明生成通用界面、执行元模式动作、校验并按 `package_id + configuration.id` 隔离存储，不识别模型、搜索服务或 Provider 等业务类型。插件不得提供任意配置 UI 代码。

Secret 由主进程加密保存，Renderer 快照只包含空值和“已配置”路径。默认的 `secret_access: owner` 允许插件通过 `seed.configuration` 读取自身声明的完整配置；`secret_access: broker` 则禁止插件读取 Secret，仅允许受控 Broker 使用，例如录音插件的转写凭据。可选的 `permission` 用于把配置绑定到系统能力权限，但不是业务服务路由。新增 Provider、字段或配置型插件不需要修改客户端；只有新增文件、录音、网络等系统能力 Broker 才属于客户端安全边界变更。

```yaml
configuration:
  id: search-providers
  schema_version: 1
  type: profiles
  title:
    en_US: Search providers
    zh_Hans: 搜索服务
  description:
    en_US: Configure one or more search providers.
    zh_Hans: 配置一个或多个搜索服务。
  profiles:
    summary_fields:
      - provider
    fields:
      - key: provider
        type: select
        span: small
        label:
          en_US: Provider
          zh_Hans: 服务类型
        options:
          - value: searxng
            label:
              en_US: SearXNG
              zh_Hans: SearXNG
          - value: tavily
            label:
              en_US: Tavily
              zh_Hans: Tavily
    actions:
      add:
        label:
          en_US: Add provider
          zh_Hans: 添加服务
      save:
        label:
          en_US: Save
          zh_Hans: 保存
      remove:
        label:
          en_US: Remove provider
          zh_Hans: 移除服务
      set_default:
        label:
          en_US: Set as default
          zh_Hans: 设为默认
        selected_label:
          en_US: Default
          zh_Hans: 默认
```

配置字段可通过 `span` 声明通用布局宽度：`small` 约占一行三分之一，省略或使用 `default` 时采用弹性默认宽度，`full` 独占整行。两个默认字段会平分一行；`small` 后跟默认字段时，默认字段会补满该行剩余空间。窄屏下所有字段统一为整行。文本、URL、密码和多行输入字段可声明同时包含 `en_US`、`zh_Hans` 的 `placeholder`；未声明时使用 Seed 的通用输入提示。字段声明 `description` 后，Seed 会在字段标签旁显示帮助图标，并在悬停或键盘聚焦时通过 Tooltip 展示说明，不占用表单布局高度。如需提供更详细的外部文档，可同时声明 HTTPS `help_url`；此时点击帮助图标会使用系统默认浏览器打开该链接。`help_url` 不允许单独声明，也不接受 HTTP 或其他协议。

`seed.panel` 管理视图的工具栏动作可将 `input.mode` 声明为 `inline`，使输入字段直接显示在插件页内，动作点击后才提交；默认模式仍为 `dialog`。页内文件字段可声明双语 `choose_label` 作为选择按钮文案，并由动作的 `input.drop_target` 指定接收整个管理视图拖放的文件字段。工具栏加入 `{ type: file_input }` 后，文件选择按钮会显示在其他动作旁，页内文件区域继续显示拖放提示和已选文件。工具栏还可声明 `{ type: select_field, field_key: model }`，引用页内选择字段并在工具栏渲染，不再在下方重复显示；`align: start` 可将该选择器放在工具栏左侧，默认位于右侧。模型选择可额外声明 `control: model_select`，使用共享组件；模型选项可提供 `group: seed | custom`、`icon_data_url`、`is_default` 与 `thinking_levels`。组件按 Seed 内置和自定义两组展示，初始选中 `is_default` 指定的模型，并提交具体模型 ID。若同时声明 `thinking_field_key` 指向另一个页内选择字段，组件会显示所选模型支持的思考等级滑杆。普通选择字段保持原样。管理视图设置 `show_header: false` 可隐藏视图自身的标题和简介，保留插件详情页头部的展示。文件选择与拖放使用相同的格式和数量校验，只传本地绝对路径，不复制原文件。每个面板最多声明一个页内输入动作。

页内字段可通过 `initial_value_path` 从插件只读数据源恢复初值；工具栏 `select_field` 或 `file_input` 可声明 `on_change_action_id`，指向同一视图内 `placement: field_change`、`input.mode: field_change` 的动作。该动作只接收对应选择字段（模型选择可同时接收思考等级字段）或文件字段，字段一变更就调用插件声明的能力；持久化方式和数据清理均由插件负责。文件清单只包含路径，插件恢复时应核对文件仍可用。

管理动作的 `select` 字段可声明固定 `options`，或声明 `options_path` 从该视图的数据源结果中读取选项数组，不能同时声明两者。动态选项元素使用 `value` 和双语 `label.en_US`、`label.zh_Hans`；Seed 用当前选项校验提交值，不解释选项的业务含义。

### 管理面板的内容与流式输出

`seed.panel` 通过 `props.blocks` 声明内容块，包括 `status` 和 `markdown`。Seed 根据这些声明统一处理加载与复制：

- **首次加载**：首次查询完成前显示与视图结构对应的骨架图；后续刷新保留当前内容。
- **复制结果**：同时声明状态块和 Markdown 块时，状态行右侧自动显示复制按钮，复制当前非空 Markdown 原文；内容为空时按钮不可用。插件无需声明复制动作。

Markdown 块的关键字段：

| 字段 | 作用 |
| --- | --- |
| `value_path` | 从数据源结果读取可恢复的 Markdown 快照。 |
| `stream_id_path` | 指向当前运行 ID；实时更新只作用于对应运行。 |
| `streaming_when` | 可选；指定启用流式 Markdown 渲染的状态。 |

实时文本由插件调用 `ctx.management.publishText()` 推送到自身已声明的 Markdown 块。`replace` 替换当前文本；`append` 追加文本，并以当前文本长度作为 `offset`。Seed 仅接受视图 ID、内容路径、流 ID 和追加偏移量都与当前状态匹配的更新，避免旧运行或重复片段覆盖结果。数据源快照仍是页面重载后的恢复依据。

### 本地服务、审计与 Sidecar

如果 `native-host` 在插件内部提供本地 HTTP、SSE 或后台任务，相关操作不会经过能力路由。插件应通过 `context.audit.record()` 上报连接、任务开始、完成、失败等结构化语义事件。Seed 自动附加插件 ID 和版本、校验允许字段并统一写入活动记录；事件不得包含令牌、密钥、消息正文或工作区绝对路径。框架路由的能力调用会自动审计，无需重复上报。连接建立、缓存刷新等仅供排障的生命周期事件应声明 `visibility: technical`，不占用用户活动列表。

本地 API 路由必须按实际用途声明 `activity`。真实用户操作使用默认的 `foreground`；健康检查、状态读取、列表同步和轮询使用 `background`；SSE 等长连接使用 `stream`。后两类只写入技术诊断，不显示在用户活动记录中，也不驱动全局忙碌状态；它们触发的嵌套能力调用与后台任务继承相同可见性。

新增 Broker 或 `native-host` 是客户端安全边界变更，需要更新 Core；新增纯计算、展示或已有 Broker 的 `sandboxed-web` 适配插件不需要更新客户端。

需要随包分发原生工具时，使用 Manifest 的 `sidecars` 声明和通用 `seed.process` Host Service。插件负责目标二进制、固定版本与摘要、命令白名单和读写风险拆分；Core 负责平台/架构选包、安装校验、工作目录路径校验、无 shell 启动、超时和取消。用户目录无需逐目录授权；仍须经过 FileBroker 的路径与读写访问检查。禁止在客户端按工具或插件 ID 添加分支。

纯计算 Sidecar 可使用 `cwd_scope: package` 以插件包根目录作为工作目录；该模式只接受 `access: read` 语义，不接受 `root_id`、`cwd` 或 `access: write`。需要读写用户目录时仍须提供文件系统根的 `root_id`，由 FileBroker 校验 `cwd` 和访问语义；`root_id` 不是目录授权凭据。输出、超时、取消与进程树清理继续使用同一安全边界。

## 5. 风险与审批

- `read`：只观察数据；
- `write`：创建、修改、移动、删除或提交数据；
- `control`：触发界面或设备流程。

所有 `risk: write` 方法都由服务端和客户端强制要求一次性审批。批准绑定用户、Seed、任务、运行、方法、完整参数哈希、请求 ID 和有效期。插件无法生成或绕过批准。

## 6. 声明式管理信息

插件只声明需要管理的资源及文案，不指定客户端页面或布局。Seed 根据能力中的 `resource_management` 决定如何呈现授权资源：

```yaml
resource_management:
  title:
    en_US: File permissions
    zh_Hans: 文件权限
  description:
    en_US: Review and manage project folders available to the plugin.
    zh_Hans: 查看和管理插件可触达的项目目录。
  empty_title:
    en_US: No project folders
    zh_Hans: 暂无项目目录
  empty_description:
    en_US: Select a project from the server first.
    zh_Hans: 请先从服务端选择项目。
```

这些声明不能注入 React、HTML 或脚本。

## 7. 构建与发布

插件仓库负责将浏览器入口和 SDK 打成单个 ESM，再生成 `.seedpkg`。包至少包含：

```text
manifest.yaml
caps/clock.yaml
dist/index.mjs
META-INF/files.sha256
```

发布流程是：构建 → 测试 → 生成 `.seedpkg` → 在 Seed Cloud 选择个人或组织归属并上传不可变草稿 → 显式提交 AI 审核 → 审核通过后显式发布。Seed Cloud 会校验整个包、包内文件的 SHA-256、Manifest 和运行时风险。企业专用插件由组织管理员授予成员使用权；客户端始终重新读取 Seed Cloud 的权威目录。

Seed Cloud 目录使用 `publisher_type: official | community` 表示运营归类；它目前不是密码学签名结论。官方与社区插件都安装到：

```text
<userData>/plugins/installed/<plugin_id>/<version>/
```

启用版本与来源记录在客户端 SQLite 数据库的 `app_settings` 中。不要根据安装目录名推断信任等级。

## 8. 发布前检查

- Manifest 与运行时的能力、版本、方法完全一致；
- 所有外部字段使用 `snake_case`；
- 所有展示文案同时提供 `en_US` 与 `zh_Hans` block-style YAML；
- 所有可预期的插件错误使用稳定错误码，并在能力 `errors` 中提供 `en_US` 与 `zh_Hans` 文案；
- 不引用客户端源码，不运行 npm lifecycle script；
- 不请求未声明 Broker，不保存 Token 和绝对目录；
- 写操作经过服务端审批且拒绝参数复用；
- 插件卸载或重载后没有遗留监听器与计时器；
- `.seedpkg` 可被 Seed 安装器严格校验；
- 类型检查、测试、构建全部通过。

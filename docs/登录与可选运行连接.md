# Seed 登录与可选运行连接

Seed 账号登录与运行服务连接是两条独立链路。统一客户端必须先通过 Seed Cloud 登录；Agent 或其他第三方运行服务由对应插件自行连接，不能用终端 ID 判断用户是否已经登录。

## 桌面登录

1. 客户端读取并验证 Seed Cloud 签名的配置发现文档。
2. 客户端生成一次性 `state`、PKCE `code_verifier` 和 `code_challenge`。
3. 系统浏览器打开发现文档中的 Cloud `/oauth2/authorize`。
4. Seed Cloud 创建短时授权请求并跳转到固定的 `/authorize` 页面。
5. 用户通过 Cloud 账号登录，并在 Cloud 页面确认客户端权限。
6. Cloud 生成短时、一次性的 authorization code，重定向到固定的自定义协议 `com.motusai.seed:/oauth/callback`。
7. 操作系统唤醒 Seed。客户端校验 `state`，再把 code、原始 PKCE verifier、client ID 和同一 redirect URI 发送给 Cloud `/oauth2/token`。
8. Cloud 校验回调地址、授权码一次性状态和 PKCE 后签发短期 access token 与可轮换 refresh token。客户端使用系统安全存储保存会话。

客户端不启动 OAuth 回环 HTTP Server，不占用 `127.0.0.1` 随机端口，也不保存上游身份提供方的 Token 和 Client Secret。应用名称、应用 ID 与图标固定为统一的 MotusAI Seed 客户端。

Seed 在 Cloud 账号登录成功后才启动插件运行时和现有本地 API 接入面；退出 Cloud 账号时停止这些本地接入面并清除本地授权会话。其他软件不能绕过 Seed Cloud 登录直接连接客户端能力。

## 可选运行连接

签名发现文档不包含运行服务地址。Seed 登录后可使用本地插件、插件市场、更新和本地能力；需要第三方运行服务时，安装并授权相应插件。插件拥有服务地址、授权、设备凭据和连接生命周期，不能复用 Seed Cloud 的 access token。连接缺失或失败不影响 Cloud 账号登录，也不参与插件目录和客户端更新。

## 实现范围

当前已经实现 Cloud 固定授权页、GitHub 上游登录、自定义协议回调、Authorization Code + PKCE、Cloud 会话刷新与撤销、登录前关闭插件运行时和本地 API。第三方运行连接属于插件；标准 MCP Server 尚未实现，未来 MCP 必须复用同一登录门禁，但不会部署在 Seed Cloud。积分系统也不属于当前实现范围。

# `.seedpkg` 与插件目录规范

本分支采用 Plugin API v2，当前只迁移官方客户端与插件。本地新包校验不等于发布平台已经支持新包；Cloud 的账号、目录和审核实现未在此轮修改。

## 包结构

`.seedpkg` 是 ZIP 容器，文件名建议为 `<plugin_id>-<version>.seedpkg`：

```text
manifest.json
main.js                      # 单个 JavaScript 文件，包含隔离入口
styles.css                   # 可选
README.md                    # 英文默认公开说明，必需
README.zh-CN.md              # 简体中文公开说明，可选
assets/icon.svg
assets/icon-dark.svg
locales/en-US.json
locales/zh-CN.json
sidecars/tool                # 可选；Windows 可使用 tool.exe
```

源码 Manifest 很轻；构建器在同一个扁平 Manifest 中生成加载协议和资源摘要：

```json
"resources": [{ "path": "main.js", "sha256": "<64位小写摘要>" }]
```

资源必须覆盖除 manifest.json 自身外的全部文件。不再添加能力 YAML、dist/index.mjs 或 META-INF/files.sha256。main.js 由 UI 和服务两张依赖图编译，宿主按角色加载；UI 不执行原生后端。安装器还验证整个包的 SHA-256。

根 manifest.json 必须声明 minAppVersion。客户端以包内要求为准，在安装和启动时强制校验；版本不足时保留数据但不运行。此次按用户要求未升版，正式发布前需要同步 SDK 和最低客户端版本。
已发布但缺少该字段的旧包仍可在目录中看到，不过会标为不兼容；需以新的不可变版本重新发布，不能原地修改旧包。

`README.md` 必须位于包根目录且非空，作为公开插件详情的默认英文说明，大小不超过 2 MiB。需要简体中文时，在同一位置提供 `README.zh-CN.md`；Seed Cloud 会按页面语言读取本地化说明，缺失时回退到 `README.md`。两份说明中使用的相对图片必须随包提供，路径必须安全且单个文件不超过 8 MiB。README 属于不可变插件版本元数据，发布后不能单独修改。

## Seed Cloud 插件目录

客户端先验证 Seed Cloud 签名的配置发现文档，再从其中的 `market_url` 读取当前账号、平台与架构可用的已发布插件。目录记录包含插件身份、国际化名称与说明、标签、发布者归类、版本、运行时、权限、能力、目标平台、不可变下载地址、SHA-256、大小和发布时间。企业专用插件还受组织成员资格约束。客户端不读取 Agent 文件系统中的 YAML 目录，也不接受本地配置覆盖 Cloud 目录地址。

现有目录的 publisher_type 表示运营归类，不表示密码学身份。发布账号和分类属于包外目录数据，不写入新 Manifest；本轮不改变 Cloud 的现有协议。

## 插件身份与所有权

- `plugin_id` 在整个官方目录中全局唯一，目录不得出现两个同 ID 的插件记录；
- 首次审核发布后，`plugin_id` 归属该发布者。后续版本必须由同一发布者身份提交；
- 下架、撤回或删除版本不释放 `plugin_id`，避免他人重新注册后形成供应链劫持；
- 发布者迁移必须通过平台审核的所有权转移流程完成；
- 显示名称允许重复，安装、升级、授权、Provider 绑定和审计只能使用 `plugin_id`；
- 同一插件的不同版本沿用同一个 `plugin_id`，且同一 `plugin_id + version` 的包内容不可变；
- 不同 `plugin_id` 可以实现相同的能力契约；能力提供方以 `provider_plugin_id + capability_id + capability_version` 精确标识。

Seed Cloud 必须在发布事务中校验全局唯一性和发布者所有权。客户端仍会拒绝同一运行时配置中重复的 `plugin_id`，但客户端校验不能替代 Cloud 审核。

`labels` 必须包含 1–3 个不重复的平台标准标签，目录与公开接口使用相同的标签字段。

Seed Cloud 必须先写入不可变的 S3 包对象，再在 PostgreSQL 事务中持久化版本与发布状态，避免目录指向不存在的版本。版本包使用不可变缓存；同一插件同一版本不得替换成不同摘要。插件发布、删除或组织授权变化后，Seed Cloud 通过事件 WebSocket 通知客户端重新读取权威目录。

列表接口会返回当前平台可用的全部版本，客户端安装时由用户选择。升级和降级共用同一安装流程；客户端对每个插件只保留 SQLite 数据库中 `active_version` 指向的当前版本，不保留旧版本包。

## 安全限制

- 最大包大小 512 MiB；
- 最大展开大小 512 MiB；
- 最大 2,000 个文件，单文件最大 512 MiB；
- 禁止绝对路径、`..`、反斜杠、NUL、设备名、符号链接；
- 禁止规范化后重复路径和大小写冲突；
- Manifest 与下载请求的插件 ID、版本必须一致；
- 不按发布者类型白名单或拒绝 Manifest 声明的运行时类型；审核会根据实际包内容、权限和本地代码风险给出结论；
- Sidecar 必须位于 `sidecars/`、声明 `executable: true` 并申请 `process.sidecar`；
- 安装不要求用户通过系统选择器逐目录授权；本地文件访问仍经 FileBroker 的路径安全检查、系统权限和能力审批；
- 安装器不执行 `package.json`、npm lifecycle 或插件安装脚本。

## 发布入口

开发者在 Seed Cloud 的“插件”页面上传 `.seedpkg`，创建时选择个人或组织归属。新版本必须由插件所有者或维护者上传；审核和发布是两个独立动作。企业专用插件由组织管理员管理成员使用权。

云安装继续使用现有统一目录和发布状态。显式开启插件开发模式的客户端另识别用户数据目录 plugins/development/<plugin_id> 中的新规范构建文件；手动放入或 npm run dev 同步使用同一发现、校验与隔离运行机制。开发源不写入云安装记录，不放宽正式包的不可变校验。关闭插件开发模式时不读取开发目录。

当前阶段不使用发布者签名环境变量。后续增加签名时，应在现有摘要、不可变对象和原子安装边界之外叠加验证，不能替代这些检查。

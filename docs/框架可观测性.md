# Seed 框架级可观测性

Seed 的活动记录和诊断证据使用同一个本地 SQLite 数据库、同一张 `observation_records` 表。活动页展示用户可理解的父子调用；上传诊断包时按时间窗从这张表导出完整记录，包括默认隐藏的技术事件。不存在另一个需要人工对账的诊断日志文件或审计表。

这是全新安装的数据契约：启动时删除旧的 `audit_entries` 表，不迁移旧活动数据，也不兼容旧的诊断 JSONL。`清空活动记录`会清空这张统一表中的全部记录。

## 证据与关联

- `trace_id` 标识一次调用链；`span_id` / `parent_span_id` 构成父子关系。一次调用的开始与结束更新同一行，保存开始时间、结束时间、耗时和最终结果。
- `request_id` 用于将宿主边界的调用与插件语义事件关联；跨 Connector、独立原生插件进程、Broker 和本地 HTTP 网关传递的关联 ID 由 Seed 生成。插件自报事件只能作为补充证据，`evidence_origin` 明确区分 `host` 与 `plugin`。
- 宿主记录插件加载/调用、Broker 调用、异常堆栈、超时和进程退出；未结束的调用在进程退出或下次启动时标记为 `interrupted`，不会永久显示“处理中”。插件自行捕获且既不报告也不表现为超时/异常退出的内部错误，宿主无法凭空还原。
- `visibility=activity` 是活动页默认可见的操作；`visibility=technical` 是同一调用链内的技术细节。活动页可切换技术详情，诊断包始终包括两者。活动列表按根调用分页；子调用不重复计入根调用总数。

数据库文件仅本机用户可读（Unix 权限 `0600`）。保留最近 90 天、约 20 万行；清理以完整 trace 为单位，避免留下没有父节点的子调用。正在运行的调用不会被清理。日志写入遇到同库事务锁时排队重试，不能同步阻塞主进程事件循环。

## 诊断包

压缩包包含 `system/manifest.json`、`activity/records.json`、`plugins/inventory.json` 和时间窗内可用的 `crashes/*.dmp`。活动与诊断记录只有 `activity/records.json` 这一份。原始错误信息及堆栈不脱敏；崩溃转储可能包含进程内存，因此应按敏感数据处理。转储优先取较新的文件，最多选取 448 MiB，为其他记录保留空间。最终包上限 512 MiB；生成、SHA-256 校验和断点续传均按流/分片处理，不把整个文件读入内存。

`.dmp` 是崩溃时可用的进程转储，不等同于完整 V8 堆快照；没有崩溃时也不会凭空生成转储。活动树能说明框架边界上的调用关系，插件内部的详细栈仍取决于宿主捕获到的异常或插件自报的错误。

## 验证口径

单元测试应覆盖同一 span 的开始/结束合并、父子查询与根分页、旧表删除、重启后悬空调用、并发 SQLite 写锁、诊断包中原始堆栈与分片上传。本地 HTTP 的成功、错误响应和抛错应产生配对的 span。Electron 冒烟与真实故障复现是独立于 TypeScript 构建/单测的验收项；未执行时不能称为已验证。
